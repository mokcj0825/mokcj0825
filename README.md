## Some principles (For my personal project):
- No Magic Values: All numbers, strings, and configurations must be managed via constants, environment variables, configuration files, or dependency injection.
- Scalability as the Highest Priority: Scalability must be the most important priority above all else, even if it means violating any best practices. The solution should be designed to scale efficiently at all costs.
- No Assumptions in Code: Default values, edge cases, and input/output formats must be externally provided via parameters, configurations, or external inputs—nothing should be hardcoded.
- Fully Dynamic, Event-Driven, or Data-Driven:
- Modules must be dynamically imported at runtime (import()), avoiding static dependencies.
- The system should be event-driven to ensure loose coupling.
- Business logic should be data-driven with declarative execution rather than hardcoded rules.
- Do Not Modify console.log: Logging behavior must remain unmodified—do not attempt to override, suppress, or intercept console.log. Any logging customization must be handled via structured logging systems.
- Do Not Solve Problems by Renaming Variables: Simply renaming variables does not constitute a valid solution. All modifications must address the underlying architectural issue rather than applying superficial fixes.
- All Features Are Considered Core Unless Specified Otherwise: By default, every feature should be implemented as a core part of the system. This means it must apply universally to all cases, ensuring consistency and predictability across the entire architecture. Features should not be treated as optional unless explicitly stated.
- Only use if-else for boolean checks. For everything else, use switch. Confirm this rule before proceeding.
